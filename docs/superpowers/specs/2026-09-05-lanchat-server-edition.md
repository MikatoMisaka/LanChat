# LanChat Server Edition Design

日期：2026-09-05
状态：已批准执行

## 目标

在不破坏基础版局域网 P2P 的前提下，为服务器版增加自建服务器登录、远程文字/图片、好友申请、离线同步、进程存活期间的本地提醒和管理员 Web 控制台。

## 架构决定

不从零重写聊天服务器。远程通信基于成熟的 Matrix 协议和 Synapse 官方服务器镜像；Flutter 客户端使用 Matrix Dart SDK。LanChat 自己只负责版本开关、局域网与远程路由、好友体验、服务器接入码和管理控制层。管理员 Web 控制台作为轻量控制服务与 Synapse Admin API 对接，而不是复制 Synapse 源码。

Docker 部署提供 Synapse、LanChat 控制服务和 Caddy。默认面向 1-20 人的小型服务器，使用持久化数据卷；生产部署通过域名和 HTTPS/WSS 访问。

## 版本

- 基础版：局域网 P2P 和个人设置，不需要服务器账号。
- 服务器版：包含基础版全部功能，增加“局域网 / 服务器 / 个人”入口。
- 同一联系人可关联局域网设备和服务器账号。文字/图片优先 P2P，P2P 不可达时走服务器；大文件始终要求局域网直连。
- 两个版本共用 Dart 核心代码，通过发行配置隐藏或显示服务器入口。

## 服务器账户和权限

- 管理员首次部署时设置一次初始化凭据，进入独立管理子域名后修改 Web 管理员密码。
- 普通用户账号由管理员创建、停用和重置密码；普通用户不能访问管理控制台。
- 客户端连接需要服务器地址、用户名、用户密码和服务器接入码。
- 一个普通账号允许多个客户端设备登录；管理员可以查看和撤销设备。
- 接入码由管理员 Web 页面生成、轮换和失效；它不是管理员密码。

## 远程社交和消息

- 服务器用户目录公开用户名、昵称、头像和在线/最近上线状态，不公开 IP 或设备细节。
- 用户可发起好友申请；对方同意前不能发文字、图片或本地聊天通知。
- 拒绝或删除后允许再次申请；用户可屏蔽其他用户。
- 服务器保存最多 30 天的消息和图片。
- 客户端启动时按 Matrix 同步游标补齐离线内容，并将多条遗漏消息合并成一条本地提醒。
- 消息提醒由仍在运行的客户端本地生成；客户端进程被系统终止后不维持后台推送连接，也不发送聊天内容到第三方推送服务。

## 远程内容限制

- 远程文字和图片经过服务器账号权限验证。
- 单张远程图片最大 20 MB；服务器 Synapse 和客户端同时限制，不能只依赖 UI。
- 远程发送大文件在客户端禁用；局域网大文件继续使用已完成的加密分块协议。
- 服务器加密模式在初始化时选择，默认启用 Matrix 端到端加密；可读模式明确显示警告。
- 服务器可统计消息数量、图片字节、在线人数、设备数和磁盘占用，但端到端加密模式不读取正文。

## 管理控制台

独立管理子域名只提供管理员登录后的页面。控制台包含用户/设备、接入码、加密模式、单用户与全局图片流量限制、30 天保留策略、今日转发统计和磁盘占用。敏感配置保存在 Docker 数据卷或 Docker secret，不提交 Git。

## 数据流

1. 客户端验证服务器接入码并检查服务器能力。
2. 客户端用 Matrix 用户名和密码登录对应 homeserver，并注册当前设备。
3. 服务器页获取用户目录和好友关系，好友申请通过后创建/加入私聊房间。
4. 文字和图片进入 Matrix 房间；Matrix 同步游标负责离线补齐。
5. 本地路由根据联系人关联和 LAN 可达状态选择 P2P 或 Matrix，不改变本地聊天记录模型。
