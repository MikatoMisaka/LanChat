# LanChat 安全传输与绿色白色体验设计

日期：2026-09-05
状态：已批准

## 目标

将当前开放式局域网聊天升级为需要显式配对的加密 P2P 聊天，同时提供可续传的大文件、Windows 桌面交互和统一的玉绿纸感界面。

## 已确认的体验决策

- 附近设备显示昵称并标记为待配对；扫码或双方确认六位数字后才成为联系人。
- 手动 IP 只发送配对邀请。升级时清空旧联系人、消息和收到的文件。
- 已配对联系人之间的文本、图片和文件均加密；本机聊天数据库不额外加密，但 Android 禁止系统备份。
- 文件保存于应用专用目录，接收前必须确认；单文件上限 5 GiB，最多三个并发传输。
- 文件分块传输，可在 60 秒无进度或两小时会话结束后保留进度；恢复由用户点击触发。
- Windows 支持文本选中复制和待确认的多文件拖放；图片支持缩放预览、桌面另存为与移动端长按保存/分享。
- 表情面板包含最近、收藏、自定义、emoji 和在线图库。
- UI 使用玉绿、暖白、淡鼠尾草绿，动效短促、可被系统减少动态效果设置关闭。

## 安全模型

每台安装生成长期身份密钥并由系统安全存储保护。Android 使用设备绑定的 Keystore 密钥加密私有值后才写入私有偏好设置，Windows 使用 Credential Manager；私钥绝不以明文进入 SharedPreferences、SQLite 或普通文件。配对时双方使用短期密钥协商出六位验证数字，用户确认后保存对方公钥。后续 TCP 连接先完成已配对身份验证和会话密钥协商，再以带递增序号的 AEAD 加密帧传输应用事件。发现包只是未经信任的候选地址，不能修改已配对联系人。

协议限制：帧头最大 8 KiB、文本最大 64 KiB、文件最大 5 GiB、单 IP 和全局连接均受限。远端 ID、文件名和文件路径永不直接用于本机路径；本地为联系人和临时文件生成独立 UUID。

## 数据与迁移

数据库升级时删除 v1 的设备和消息数据，并删除旧文件目录。新数据库保存已配对联系人、消息、待传输任务、表情收藏与最近使用记录。私钥不以明文进入 SQLite 或 SharedPreferences。所有联系人删除、传输状态和文件清理使用事务或可恢复的临时文件状态。

## 文件传输

发送方先发送加密文件邀请，接收方确认后才发送分块内容。每块经过认证，接收方写入随机 `.part` 文件；完成后校验总摘要并原子改名。恢复任务保存已接收偏移量和原文件摘要，双方再次在线时仅显示恢复按钮。应用专用目录外的保存动作必须由用户在系统文件选择器中明确选择。

## UI

桌面采用浅色边栏加留白聊天主区，颜色为暖白背景、玉绿操作色与淡绿色状态面。聊天消息可选中，文件拖放进入待发送托盘，图片用可缩放沉浸预览。移动端保持单栏，将相同的组件层级和色彩语义映射为底部输入区与全屏预览。动效限定在消息出现、面板切换、拖放状态和图片打开，时长 180-240ms，并遵从 `MediaQuery.disableAnimations`。

## 验收

- 未配对设备无法写入联系人、消息或文件。
- 篡改、重放、超限帧、非法路径和超时连接被拒绝。
- 5 GiB 文件可被确认、暂停并恢复，接收路径不会逃逸应用目录。
- Windows 支持文本复制、拖放、图片预览和另存；移动端支持预览、保存与分享。
- `flutter analyze`、全部单元/组件测试、Android release 和 Windows release 构建成功。
