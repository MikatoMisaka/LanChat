# LanChat 轻量服务器版设计

日期：2026-09-06
状态：已批准执行

## 目标

LanChat 服务器版面向朋友之间建立的私有聊天组。服务器拥有者通过其他方式把邀请码和服务器地址发给朋友，朋友在客户端提交加入申请，管理员在 Web 页面审批。管理员不需要创建 Matrix 账号、填写 Synapse token 或维护多套认证配置。

## 使用方式

- 客户端只需要服务器地址、端口、邀请码、用户名、密码和昵称。
- 服务器地址可以是 IP 或域名，端口由部署者决定；框架不强制绑定域名。
- 公网部署仍建议使用 HTTPS，但证书不属于 LanChat 管理员日常配置。
- 邀请码支持群组邀请码和单人邀请码。邀请码通过外部渠道发送，服务器只负责校验和记录申请。
- 用户申请后进入待审批状态。管理员可以通过或拒绝申请。
- 用户名和密码属于 LanChat 账号，不向用户暴露 Matrix/Synapse 账号。
- 每台新设备单独审批；管理员可以查看、撤销和禁用设备。

## 服务器职责

- 保存用户、设备、申请、会话和必要的消息索引。
- 转发并缓存客户端加密后的消息和图片。
- 默认不解析聊天正文，管理员只能看到用户状态、设备状态、流量和存储信息。
- 远程图片最多 20 MB；大文件仍然通过局域网直连。
- 消息和图片默认保留 30 天，保留时间可由管理员修改。
- 服务器端的 Matrix/Synapse 如果继续使用，只作为内部存储和同步引擎，不出现在用户或管理员的配置界面中。

## 管理员职责

- 第一次打开管理页时，使用服务器首次启动生成的一次性初始化口令设置管理员密码。
- 查看服务器健康、在线用户、设备、存储和流量。
- 审批或拒绝加入申请。
- 查看用户状态、禁用用户和撤销设备。
- 轮换群组邀请码。
- 修改消息保留时间和图片/存储限制。

## 页面设计

管理后台采用低密度的控制室布局：深墨绿色文字、暖白背景、青绿色操作色、少量橙色状态提示。首页先展示状态和待处理申请，用户管理放在独立页面；设置项只在需要时展开。页面必须支持手机和桌面浏览器，不使用外部 CDN，不依赖 JavaScript 框架。

## 安全边界

- 邀请码只能证明申请者知道群组口令，不能直接获得成员资格。
- 管理员审批后才创建有效用户会话。
- 每台设备有独立会话，可单独撤销。
- 聊天正文在客户端加密，服务器缓存密文。
- 公网 HTTP 仅作为明确的部署选项；客户端在使用非 HTTPS 地址时显示安全提示，不把 IP 连接强行改成域名证书模式。
- 所有管理员操作需要管理员会话；初始化口令使用一次后立即失效。

## 兼容策略

现有局域网 P2P 功能保持不变。服务器版先提供独立的远程联系人和聊天入口；同一联系人在局域网与服务器之间的自动合并路由不阻塞本次服务器版交付，后续通过联系人关联层加入。
